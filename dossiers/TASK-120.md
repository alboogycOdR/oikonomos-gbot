  **Migration** `infra/postgres/migrations/009_group_threads.up.sql`/`.down.sql`:
  - `threads.role_id` made nullable; old blanket `UNIQUE(role_id)` constraint replaced with a partial unique index `threads_role_id_key ON threads(role_id) WHERE role_id IS NOT NULL` — 1:1 threads still get uniqueness, multiple future group threads (role_id null) can coexist.

  **`packages/db/src/threads.ts`**: added `ThreadMember` type, `addThreadMember`/`listThreadMembers` accessors (idempotent upsert + ordered list). Updated the two existing `INSERT ... ON CONFLICT (role_id)` statements (`createThread`, `getOrCreateThreadForRole`) to `ON CONFLICT (role_id) WHERE role_id IS NOT NULL` — required because Postgres only matches a partial unique index for conflict inference when the inference clause's predicate is given explicitly; without it these calls threw `no unique or exclusion constraint matching the ON CONFLICT specification` once role_id became nullable. Kept the exported `Thread.roleId` type as plain `string` (not `string | null`) with an explanatory comment — every accessor in this file only ever produces 1:1 threads with a real roleId today (group-thread creation is TASK-121's own new code path with its own return shape), so widening the type here would force an unrelated null-check ripple into `services/control-api/src/app.ts`'s existing 1:1-only handlers, which are out of this task's `Owned_Paths`. `toThread()` throws loudely if it ever encounters a null `role_id` row instead of silently coercing, so a future gap would fail loud rather than lie.
