## 4. Operational knowledge that is NOT obvious from the repo

**(a) Two local patches to `framework_owned` pack files will be REVERTED by the next `sync_from_pack.py`.** Both are load-bearing — if the L2 supervisor starts dying again, check these first:

- `scripts/validate_plan.py` — accepts `<TOKEN>: detail` Blocked_Reasons. Without it, any builder blocking with an explanation makes PLAN illegal and **halts the loop** (killed two runs). Finding #14.
- `scripts/tg_commands.py::git_pull` — now `fetch` + `merge --ff-only`, never `pull --rebase`. Without it, a diverged origin **corrupts the main checkout into detached-HEAD-mid-rebase while the loop runs** (killed one run, cost a recovery). Finding #15.

Both are marked `LOCAL PATCH` in-file with the reasoning. Re-apply after any pack sync until upstream ships them.

**(b) Do NOT spawn PowerShell as a child process from Bash.** Alister asked for this explicitly, and it was killing dispatches. Dispatch either by asking Alister to run it in his terminal, or via the **PowerShell tool** with `run_in_background`:
```
powershell -ExecutionPolicy Bypass -File scripts\dispatch.ps1 -Builder GB|CX|S5
```
`dispatch.ps1` runs the builder **synchronously** — always background it, never block a foreground call on it.

**(c) Worktree discipline — this cost real work before it was fixed.**
- There is a **dedicated review worktree**: `C:\CLAUDECODE_TOOLSETS\wt-review-oikonomos`. Point every adversarial review there.
- **Never point a review at a builder's worktree.** Doing so once destroyed an in-progress task (039's first attempt) — the review's checkouts reset the tree under the live builder.
- **Never delete a task branch that is at `needs_review` with unmerged work.** Doing so orphaned a reviewed commit (033); it was recoverable from the reflog, but only because the review agent noticed.
- Builder worktrees left on stale merged branches are harmless — dispatch resets them.

**(d) PLAN.md edits: write them from a Python file, not inline `python3 -c` in Bash.** Backticks and `$(...)` in finding text get shell-interpreted and silently mangle the record (happened once; had to rewrite). Use `scratchpad/*.py` + `python <file>`.

**(e) Review standard that actually found things.** Every protected task got an adversarial subagent that *mutates the control and requires a test to turn red*. "Tests pass" was never accepted. This caught, among others: a cross-tenant replay bypass, a tier-escalation bypass with no audit event, three real backup-drill bugs, a canary suite where 2 of 8 only ever skipped, and a control nothing could invoke. Per-file review is necessary but **not sufficient** — the whole-system Fable pass found the CRITICAL that nine per-file passes structurally could not see.

## 8. One thing worth carrying forward

The most valuable finding of this session was not a bug in anyone's code — it was that **a control can be correct, fully tested, mutation-proven, and still worthless because nothing calls it.** The entire E4 stack was in that state until TASK-042. When reviewing E6, ask of every control: *what invokes this in production, and what fails if it stops being invoked?* That question, more than any test count, is what ADR-005 is really about.
