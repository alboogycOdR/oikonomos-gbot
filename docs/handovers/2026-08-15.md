## Traps discovered

### Five bugs in the DEVDEPARTMENT pack (all documented inline with links)
1. **dispatch.ps1 stdin prompt escaping**: cmd /c mangles embedded newlines in arguments; workaround: write prompt to file, redirect stdin (verified fix)
2. **PowerShell Tee-Object UTF-16 encoding**: codex via `codex exec` reads UTF-8, but Tee-Object writes UTF-16 LE; regex never matched interleaved NULs; workaround: re-encode via UTF8Encoding(false) before extraction
3. **dispatch.ps1 stderr EAP=Stop abort**: codex's version banner on stderr throws under ErrorActionPreference=Stop, aborting pipeline; workaround: set EAP=Continue during builder execution
4. **control.py hardcoded builder units**: claim/extract had `choices=["GB","CX"]`, so S5 dispatch failed "invalid choice: 'S5'"; workaround: derive units from builder_registry, validate fail-closed
5. **atlas_core.is_ignored() prefix-match bug**: trailing-slash `.gitignore` entries (e.g. `node_modules/`) only exclude the prefix path, not nested ones; in pnpm monorepo every workspace has its own `node_modules`. Workaround: glob-form excludes in autopilot.json's `atlas.exclude` (fnmatch's `*` spans `/`). Upstream fix needed in pack.

### ADR-003 fail-open trap
`role_grants.max_tier` is named and documented as a **ceiling** (caps tier downward). The resolver parameter it superficially matches expects a **floor** (caps tier upward). Passing the column directly type-checks, runs, and silently fails open: a role capped at T1 against a T3 capability resolves to `max(T3, T1) = T3`. **TASK-016 (OIK-027 broker handler) MUST include a negative test where ceiling < default still denies, and reference ADR-003.**

### Manifest grant pattern
TASK-005, TASK-006, TASK-007 each lost a full session to the same ownership block: source territory granted, but not the `package.json` declaring the new dependency. TASK-009 inverts this: grants manifests at decomposition time so implementation tasks own only src/test. **For any future task that adds a runtime dependency, pre-grant its workspace manifest and the lockfile at decompose time.**

### Hook scoping in ES modules monorepos
TASK-001 set `"type": "module"` at repo root (correct per Handover §3). Node resolves module type from nearest package.json, so all seven CommonJS hooks in `.devteam/hooks/` became ES modules. A crashed hook exits 1, which Claude Code treats as non-blocking, so the territory firewall **failed open** and stopped enforcing Owned_Paths for S5. Fixed by scoping hooks back to CommonJS with `hooks/package.json`. S5's TASK-003 work was audited manually as a result (clean). **Test any future DEVDEPARTMENT repos with S5 dispatch early to catch this.**
